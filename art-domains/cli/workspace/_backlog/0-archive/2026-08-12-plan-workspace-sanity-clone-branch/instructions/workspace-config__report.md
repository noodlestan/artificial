## Feedback

### For the planner

- **Where:** `plan__pseudo__config.md` → "Function: loadWorkspaceConfig" / "How the compiled CLI reads a TS config (Vite-style)"; `ops/_adr/cli.art` → "Runtime Config Loading — esbuild Bundle-at-Runtime".
- **Problem:** The authored manifest imports the package entry (`src/index.ts`), which also hosts the commander CLI. esbuild bundling of the manifest therefore pulls the CLI entry in, and with it `commander@12` (CommonJS; `lib/command.js` calls `require('node:events')`). esbuild's CJS→ESM interop leaves a `__require` shim that throws `Dynamic require of "node:events" is not supported` when the temp bundle is imported in Node ESM. Reproduced by running the loader algorithm against the real `.art-workspace.mts`: the import fails with exactly that error. The pseudo's note ("bundling pulls the CLI entry in (commander, simple-git)... acceptable for a dev tool") assumed the bundle would merely be large — it is actually broken. As specified, `loadWorkspaceConfig` cannot load the authored manifest; the next commit (`sanity-command`) hits this on first consumption.
- **Decision:** This commit's required validations (unit tests on self-contained fixtures, nodenext type-check, CLI boot, build) all pass and the loader's first real consumption belongs to `sanity-command`, so the instruction was implemented verbatim without redesigning the plan. The defect is documented here with a fix.
- **Ready-to-apply snippet for `plan__pseudo__config.md` / `ops/_adr/cli.art`:**

```markdown
Split the config authoring surface into a `./config` subpath export (types +
`defineConfig` + `locateCheckouts` + `loadWorkspaceConfig`, no runtime imports)
and point the authored manifest at `@art-domains/workspace-cli/config`. Bundling
the manifest then inlines only the config module; the CLI entry (commander,
simple-git) is never pulled into the temp bundle. Without this split,
`loadWorkspaceConfig` fails at runtime: commander is CommonJS and esbuild's
CJS→ESM bundle leaves a `__require('node:events')` shim that throws in Node ESM.
```
